# Upgrade guide

This folder uses TUEL Blueprint Standard 1.1.0 with Policy Contract 1.0.0 and Data Layout 1.0.0. It adds a versioned safety floor, an operations workspace, an inbox for temporary source material, ordinary operator and reality-checker role guides, work receipts, incident handling, an owner-reviewed memory process, and routine-level AI adoption guides.

The adoption guides add a Readiness gate and four stages: Assisted, Repeatable, Supervised operations, and Intent-led Business OS. A stage belongs to one routine, never the whole business. No stage grants outside authority, and no routine promotes itself.

## Before replacing files

1. Make a copy of the installed folder.
2. Read the proposed changes to `CLAUDE.md`, approval rules, and retention rules.
3. Review any new or changed routine, adoption stage, work-packet boundary, schedule, source list, and permission recommendation.
4. Ask the owner to accept, edit, or reject each policy change.
5. Replace shipped capability files only after approval.

Never overwrite the owner's `business/`, `assets/`, `reports/`, `operations/`, or `inbox/` content. Merge changes around owner edits. A new download is not permission to change saved instructions, connection access, schedules, or outside systems.

A new or materially changed routine returns to Manual permission. An upgrade cannot advance a stage. Adoption stages cover A Observe and B Draft only; the separate reviewed-memory workflow remains the only standard C Internal write and still requires fresh approval of the exact change.
